## Общие шаги отладки

Перед открытием тикета поддержки, три команды решают большинство проблем:

```bash
# 1. Проверьте, что API-ключ валиден и попадаете в правильный workspace
curl https://api.revroute.ru/workspaces/proj_xxx \
  -H "Authorization: Bearer $REVROUTE_API_KEY"

# 2. Проверьте путь редиректа короткой ссылки
curl -I https://revroute.ru/your-key

# 3. Инспектируйте, что реально отправил analytics-скрипт
# DevTools → Network → фильтр "api.revroute.ru"
```

При падении запроса тело ответа всегда содержит `error.code` и `error.message`. Скопируйте оба в тикет — это даёт root cause за один round-trip.

## Где смотреть в дашборде

- **Вкладка Events** (`/<workspace>/events`) — каждый клик, лид и продажа в реальном времени с сырым payload'ом
- **Логи вебхуков** (`/<workspace>/settings/webhooks/<id>` → Logs) — каждая попытка доставки с request/response
- **Логи API** (`/<workspace>/settings/tokens/<id>` → Logs) — недавние запросы с этим API-ключом, коды статуса, тайминги

Эти три представления решают ~80% вопросов "почему не работает" до чтения кода.

## Статус и известные инциденты

- **Статус:** [status.revroute.ru](https://status.revroute.ru)
- **История инцидентов:** на странице статуса есть история прошлых инцидентов — если проблема началась в конкретное время, проверьте там первым.

Если в дашборде всё здорово, и страница статуса зелёная — проблема почти наверняка в вашей конфигурации. Пройдите соответствующую страницу ниже.
