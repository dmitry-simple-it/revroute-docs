UTM бесплатны, но разрозненные UTM убивают аналитику. Несколько минут на конвенции в начале — это часы сэкономленной чистки потом. RevRoute автоматически добавляет UTM из настроек ссылки или вы можете хардкодить их в destination URL — в любом случае, значения, которые вы отправите сегодня, окажутся в вашем DWH на годы.

## Пять стандартных UTM

| Параметр | Назначение | Пример |
| --- | --- | --- |
| `utm_source` | **Откуда** трафик — конкретный издатель, партнёр или приложение | `partner-acme`, `newsletter`, `twitter` |
| `utm_medium` | **Как** доставлен — категория канала | `affiliate`, `email`, `social`, `cpc` |
| `utm_campaign` | **Зачем** — маркетинговая инициатива | `q2-launch`, `black-friday-2026` |
| `utm_term` | Ключевое слово платного поиска (опционально) | `marketing+automation` |
| `utm_content` | Вариант — креатив, кнопка, размещение | `hero-cta`, `footer-banner` |

Используйте **все пять**, когда уместно. Пустые UTM нормальны; недостающие UTM, которые вы потом захотите — нет.

## Конвенции именования

Согласованная схема важнее идеальной. Выберите правила и следуйте им:

- **Всегда lowercase.** `Affiliate` и `affiliate` — разные строки в отчёте. Принудительно lowercase на источнике.
- **Дефис, не подчёркивание и не пробел.** `q2-launch` лучше `q2_launch` и `Q2 Launch` (становится `Q2%20Launch`).
- **Только ASCII.** Закодированная кириллица / эмодзи в UTM технически легальны, но враждебны дашбордам.
- **Без timestamp'ов в source/medium.** Если нужны — кладите в `utm_campaign` (`spring-2026`).
- **Стабильно, не описательно.** `utm_source=newsletter-weekly` — хорошо; `utm_source=newsletter-about-our-new-feature` — нет (тема идёт в `utm_campaign`).

## Organic vs paid

Самое полезное разделение в аналитике — «заплатил ли я за этот клик?». Держите его видимым в `utm_medium`:

| Канал | `utm_medium` |
| --- | --- |
| Affiliate / партнёрская программа | `affiliate` |
| Инфлюенсер (разовый, оплачено) | `influencer-paid` |
| Инфлюенсер (органическое упоминание) | `influencer-organic` |
| Email-рассылка | `email` |
| Соц.сети — платное | `paid-social` |
| Соц.сети — органика | `social` |
| Платный поиск | `cpc` |
| Дисплей | `display` |
| Direct mail / QR-коды | `offline` |

Тогда `WHERE utm_medium IN ('cpc','paid-social','display','influencer-paid')` — это ваша платная когорта, всегда.

## Рекомендуемая таксономия source

`utm_source` отвечает на вопрос «если я захочу написать владельцу этого трафика, кому?». Для партнёрских программ это **один source на партнёра**:

```
utm_source=partner-acme
utm_source=partner-bob-blog
utm_source=partner-marketing-podcast
```

RevRoute проставляет это автоматически для program-ссылок — каждая партнёрская ссылка включает `utm_source=<partner-slug>`, чтобы вам не нужно было думать.

Для собственных каналов:

```
utm_source=newsletter            # основной список
utm_source=newsletter-prospects  # конкретный список
utm_source=twitter
utm_source=youtube
utm_source=blog
```

## Именование кампаний

Кампаниям помогает структурированный формат:

```
{quarter}-{theme}-{audience?}
q2-launch
q4-black-friday
q1-2026-pricing-update-existing
```

Префикс с временем позволяет дашбордам хронологически сортировать кампании без парсинга дат. Суффикс audience добавляйте, когда одну тему запускаете на разные сегменты.

## Где задавать UTM

Три варианта, в порядке предпочтения:

1. **На уровне короткой ссылки** (поля `utm_source`, `utm_campaign` в настройках ссылки). RevRoute добавляет их при редиректе. Лучше всего для программных ссылок — партнёр не сможет случайно их удалить.
2. **В destination URL.** Работает, но изменить их без обновления всех мест использования невозможно.
3. **Через отдельный script-tag** (через встроенный UTM-tracking в `<DubAnalytics />`). Лучше всего для клиентских инструментов, читающих UTM до редиректа.

Не смешивайте #1 и #2 — дублирующиеся параметры создают путаницу.

## Миграция: чистка legacy UTM

Если унаследовали хаотичную UTM-историю:

<Steps>
  <Step title="Аудит">
    Выгрузите 6 месяцев click-данных, сгруппируйте по `utm_source` и `utm_medium`, посмотрите длинный хвост. Найдёте опечатки, разные регистры, единичные значения.
  </Step>
  <Step title="Решите консолидацию">
    Например, «все варианты `email` / `Email` / `e-mail` мапятся в `email`». Запишите.
  </Step>
  <Step title="Применяйте в DWH, не в RevRoute">
    Мапьте старые UTM в канонические в таблице `dim_utm_source` в DWH. Не пытайтесь переписать историю в RevRoute.
  </Step>
  <Step title="Зафиксируйте новые ссылки">
    Дальше — задавайте UTM на уровне ссылки (вариант #1) и задокументируйте конвенцию в runbook создания ссылок.
  </Step>
</Steps>
