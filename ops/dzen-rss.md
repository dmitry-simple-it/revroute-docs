# RSS → Дзен: подключение и редакционный процесс

Проверка источников: 2026-10-04. Реализована сторона сайта; импорт в канал `revroutelinks` ещё не проверен.

## Что реализовано

- `GET /feed/zen.xml`: RSS 2.0, UTF-8, полный текст в `content:encoded`, стабильный GUID, реальная обложка в `enclosure`.
- В ленту входят только записи из `content/blog.ts` с `dzen.enabled === true`. Первая согласованная статья — `/blog/shorten-link-no-signup`, дата публикации `2026-10-04`, экспорт в режиме `draft`.
- Дата вычисляется из `dzen.publishedAt` либо исходной `date`; будущие публикации не выдаются до наступления времени. Повторный запрос не меняет GUID или дату.
- `mode: 'draft'` (и отсутствие mode) добавляет `native-draft`; `mode: 'publish'` убирает директиву черновика. Реальное выполнение директивы должен подтвердить пилот в Дзене.
- Некорректная включённая статья вызывает HTTP 503. Ошибка не превращается в неполную статью.
- Локальный импорт Markdown и превью не добавляют материал в массив `posts` и не включают доставку.

## Разметка

| Исходник | Выдача для Дзена |
| --- | --- |
| Абзац / rich-p | p с экранированным текстом |
| Подзаголовки | h2, h3 |
| Выделение / курсив | b, i |
| Ссылка | a href с абсолютным HTTP(S)-адресом |
| Списки | ul/ol, li |
| Картинка с подписью | figure, img, figcaption |
| Цитата | blockquote, p |
| CTA | Абзац текста и обычная ссылка |
| Таблица | Список строк с подписями каждого столбца; все значения сохранены |
| Stats | Список значений с названиями |
| React mock | Ошибка: сначала заменить явно подготовленным изображением |
| FAQ / источники | Подзаголовки, абзацы и ссылки; без details/summary |

CSS, JavaScript, iframe, таблицы и кнопки не экспортируются. URL из примеров в тексте не переписываются: в статье про UTM нельзя удалять смысловые параметры. Обложка в enclosure не добавляется искусственно в начало тела. Первое изображение статьи может влиять на карточку — проверить фактический результат.

Для изображений принята консервативная внутренняя проверка: минимум 700×320, JPEG/PNG/GIF/WebP, реальные размеры и ненулевое число байтов. Это политика экспортёра, а не утверждение об универсальном актуальном минимуме Дзена. Импортёр файлов пока читает JPEG/PNG.

## Локальные команды

```powershell
npx tsx scripts/build-dzen-draft.ts --source=D:/revroute-os/40-marketing/articles/dzen-shorten-link-no-signup-2026-05.md --slug=shorten-link-no-signup --date=2026-10-04 --image-map=content/dzen/pilot-image-map.json
npx tsx scripts/build-dzen-preview.ts --draft=content/dzen/drafts/shorten-link-no-signup.json
npm run test:dzen-rss
npx tsc --noEmit
```

`--date` в локальном черновике — предполагаемая дата. Перед размещением на сайте поставить фактическую дату публикации; не обновлять её автоматически при редактировании.

Импортёр извлекает только раздел «Черновик статьи», исключая frontmatter и бриф. Он сохраняет текст, выделение, ссылки, простые списки и цитаты; связывает отдельный курсивный абзац после изображения с figcaption. Неизвестная разметка и сложные вложенные списки останавливают импорт. Карта изображений явно заменяет маленькие мобильные кропы оригинальными настольными снимками; изображения копируются без изменений. Узкие кропы 388 px не увеличиваются искусственно.

Файлы проверки: `tmp/dzen-rss/shorten-link-no-signup/preview.html` и `preview.xml`. Это локальная проверка структуры, не эмуляция редактора Дзена.

В локальном dev-сервере статья доступна также по адресу `/blog/preview/shorten-link-no-signup` в общей дизайн-системе сайта. Этот маршрут работает только в development, закрыт от индексации и не добавляет черновик в блог или RSS. В production он возвращает 404.

## Подключение канала — ещё не выполнено

Для подтверждения сайта добавлен файл `public/zen_sM8sn1YLWt9qjw8zyWdiBOAZz3kJc8NuOjMA4Xq3CLLYScJTIadyt9zFwAp1l8KZ.html` с точным метатегом из Дзен-студии. После выкладки он должен отвечать HTTP 200 по одноимённому пути в корне `https://revroute.ru/`. Подготовка файла не означает, что проверка в Дзене уже прошла.

В открытых настройках канала «Кросспостинг в Дзен» доступны YouTube, Telegram и VK Видео Live. Поля подключения RSS в этом разделе нет. Подтверждение домена само по себе не доказывает подключение RSS; процесс приёма ленты для этого канала ещё нужно установить.

1. Проверить в Студии авторского канала, доступно ли подключение сайта/RSS. Названия пунктов заранее не считаем подтверждёнными.
2. Уточнить в интерфейсе или поддержке, подходит ли обычный авторский канал для импорта и какой формат требуется: канал или схема для сайтов-партнёров/Дзен Новостей. Регистрация СМИ и новостная интеграция не предполагаются автоматически.
3. Согласовать правила подключения: подтверждение владения доменом, число стартовых материалов, актуальность и поддерживаемые директивы. Не генерировать фиктивные статьи и даты ради требований.
4. Опубликовать утверждённый исходник на сайте и включить его в RSS с `mode: 'draft'`, сохраняя исходную дату и guid. Первая проба должна подтвердить создание черновика, а не полагаться на директиву без проверки.
5. После выкладки проверить публичный URL ленты и всех изображений без авторизации. robots.ts уже разрешает эти пути через правило для *; отдельный неподтверждённый User-agent Mail.ru не добавлен. При блокировке CDN/WAF получить список роботов/IP у поддержки.
6. Передать адрес `https://revroute.ru/feed/zen.xml` через доступный в канале процесс подключения; дождаться результата приёма.
7. В Дзене проверить заголовок, порядок трёх изображений и подписи, подзаголовки, выделение, все ссылки, карточку и мобильный вид. Затем включать режим публикации для проверенных материалов.

Если подключение требует 10 стартовых материалов, пилот из одной статьи не завершит регистрацию ленты: сначала нужна реальная редакционная подборка. Это внешняя предпосылка, а не причина автоматически отправлять старый блог.

## Источники и границы подтверждения

Официальные адреса справки найдены, но содержимое не удалось прочитать веб-инструментом:
- [Разметка RSS](https://dzen.ru/help/ru/website/rss-modify.html).
- [Единый RSS сайтов-партнёров](https://dzen.ru/help/ru/news/seamless/rss.html).

Изучены первичные источники авторов интеграций, а не официальное подтверждение для нашего аккаунта:
- [Prozen — описание плагина](https://wordpress.org/plugins/prozen-integration-for-dzen/): совместимая лента, нормализация контента; приём в канале как итоговая проверка.
- [Dzen RSS Feed — спецификация реализации](https://github.com/Bormotoon/dzen-rss-feed/blob/main/docs/dzen-rss-spec.md): семантика RSS, whitelist, native-draft, format-article и требования к стартовой подборке.
- [Zhekich Feed Generator](https://wordpress.org/plugins/zhekich-feed-generator-for-dzen/): сообщает о переходе сайтов-партнёров на единую схему с 2026-07-13, описывает преобразование strong/em в b/i. Применимость новостного процесса к нашему авторскому каналу не подтверждена.

В реализации лимиты заголовка 140 символов, ленты 10 MiB и подборки 500 статей — консервативные ограничения проекта. Они не доказывают текущие лимиты аккаунта. Не обещаем импорт за 5–15 минут, модерацию за 72 часа, универсальный запрет UTM или конкретный метод DNS-подтверждения.

Настройки «Свой сайт» прочитаны в открытой Дзен-студии: выбран метод HTML-файла, до выкладки файла интерфейс показывал ошибку получения HTTP 200. Проверка прав на сайт и подключение RSS подтверждаются отдельно в интерфейсе после выкладки.


## Как включить первую утверждённую статью

Первая статья уже согласована: `content/dzen/approved.ts` импортирует её JSON и включает запись в массив с `enabled: true`, `mode: 'draft'`, датой `2026-10-04`. Одна запись используется и страницей `/blog/<slug>`, и RSS. Для следующих согласованных материалов применяется тот же процесс:

```ts
import type { BlogPost } from '../blog'
import draft from './drafts/shorten-link-no-signup.json'

const post = draft.post as BlogPost
export const approvedDzenPosts: BlogPost[] = [{
  ...post,
  date: 'ФАКТИЧЕСКАЯ_ДАТА_ПУБЛИКАЦИИ',
  dzen: {
    ...post.dzen!,
    enabled: true,
    mode: 'draft',
    // При необходимости: publishedAt с точным временем и часовым поясом.
  },
}]
```

Заменить дату на валидную ISO-дату или задать publishedAt. Пример не вставляется автоматически. При смене slug сохранить существующий guid. Режим publish включается отдельно после проверки импорта. Повторно пересоздавать GUID ради повторного импорта нельзя.
