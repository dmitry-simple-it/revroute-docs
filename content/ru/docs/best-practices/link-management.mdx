Первые 100 ссылок укладываются в один список. Следующие 10 000 — по папкам. Следующие 100 000 — по системе. Эта страница описывает систему до того, как она вам понадобится.

## Папки vs теги

| | Папка | Тег |
| --- | --- | --- |
| Ментальная модель | Картотека | Стикер |
| Ссылка принадлежит | Ровно одной | Множеству |
| Права доступа | Да — ограничивать доступ по папке | Нет |
| Влияет на URL | Нет | Нет |
| Правильный инструмент для | Владения командой / проектом | Сквозных атрибутов |

**Папки — для владения.** Ссылка маркетинга на Q2-лонч живёт в папке `marketing/`. Эксперимент growth-команды — в `growth/`. Права наследуются — viewer на `marketing/` видит каждую ссылку внутри без per-link грантов.

**Теги — для всего остального.** Канал (`channel:email`), кампания (`campaign:q2-launch`), язык (`lang:en`), статус (`status:archived`). Применяйте к ссылке много тегов.

## Масштабируемая таксономия

```
folders/
  marketing/
    campaigns/
    evergreen/
  growth/
    experiments/
    paid/
  product/
    onboarding/
    feature-launches/
  partners/
    program-a/
    program-b/
  internal/
    staging/
    testing/
```

Три уровня вложенности достаточно. Дальше навигация медленнее поиска.

Схемы тегов — выберите конвенцию `key:value` и придерживайтесь:

```
channel:email
channel:social
channel:partner
channel:paid
lifecycle:test
lifecycle:active
lifecycle:retired
priority:high
priority:low
```

`key:value`-теги массово ищутся (`channel:email AND lifecycle:active`) и легко фильтруются из API.

## Retention и lifecycle

Старые ссылки копятся. Без политики retention окажетесь с тысячами мёртвых `lifecycle:test`-ссылок, мусорящих в автокомплите. Простая схема:

| Тег | Значение | Действие |
| --- | --- | --- |
| `lifecycle:test` | Создана в dev/QA | Архив через 30 дней, удалить через 90 |
| `lifecycle:campaign` | Одноразовая кампания | Архив после окончания, удалить через 180 дней |
| `lifecycle:evergreen` | Долгоживущая ссылка (доки, careers и т.д.) | Никогда не удалять |

По умолчанию архивируйте (не удаляйте) — история аналитики сохраняется, ссылка возвращает `410 Gone` вместо `404`. Удаляйте только после того, как прошло достаточно времени, чтобы входящий трафик исчерпался.

В дашборде есть встроенный **Cleanup** во `Настройки → Workspace → Cleanup`, который показывает:

- Ссылки с 0 кликов старше 90 дней
- Ссылки с одним кликом старше 30 дней
- Сломанные destination'ы (4xx/5xx при последней проверке)

Просматривайте ежемесячно.

## Короткие домены

Большинство workspace'ов стартуют на `revroute.ru` и переходят на брендированный короткий домен (`go.yourbrand.com`) по мере роста библиотеки. Рекомендуемая схема:

| Домен | Использование |
| --- | --- |
| `revroute.ru` | Одноразовые тестовые ссылки, внутреннее использование |
| `<brand-short>.<tld>` (напр. `go.acme.com`) | Customer-facing, маркетинг |
| `partners.<brand-short>.<tld>` (напр. `r.acme.com`) | Партнёрские реф-ссылки |
| `<brand-event>.<tld>` (напр. `acmecon.com`) | Крупные разовые кампании |

Брендированные домены значительно увеличивают CTR и доверие (~30% в наших клиентских данных). DNS-настройка — один CNAME + один TXT, см. [Решение проблем с доменом](/docs/troubleshooting/domain-config), если SSL не выдаётся.

## Именование коротких ключей

Путь после домена (`/launch`, `/q2-event`) — это то, что видят и запоминают пользователи. Несколько правил:

- **Lowercase, через дефис** — `q2-launch`, не `Q2_Launch`.
- **Кратко, но осмысленно** — `pricing` лучше `p` и лучше `our-new-pricing-page`.
- **Стабильно** — никогда не переименовывайте опубликованный ключ. Создавайте новый, архивируйте старый.
- **Предсказуемо для QR** — `go.acme.com/conf` читается на печатном размере лучше, чем `go.acme.com/a8d3F2`.

Пусть RevRoute сам генерирует случайные ключи для high-volume программных ссылок (campaign-tools, deep-links). Маркетинговые курируйте вручную.

## Bulk-операции

Когда ссылок больше нескольких сотен, освойте bulk-эндпоинты:

- `POST /links/bulk` — создание до 100 ссылок за запрос, удобно для seeding партнёрских deeplink'ов
- `PATCH /links/bulk` — массовая разметка тегами, перемещение по папкам, архивирование
- `DELETE /links/bulk` — очистка `lifecycle:test`-ссылок из CI

Примеры:

```bash
# Архивировать все тестовые ссылки старше 30 дней
curl -X PATCH https://api.revroute.ru/links/bulk \
  -H "Authorization: Bearer $REVROUTE_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "filter": { "tags": ["lifecycle:test"], "createdBefore": "2026-04-25" },
    "update": { "archived": true }
  }'
```

## Управление доступом

Папки поддерживают три уровня прав на участника workspace или группу:

| Уровень | Может |
| --- | --- |
| Viewer | Видеть ссылки и аналитику, без правок |
| Editor | Создавать/редактировать ссылки в папке |
| Owner | Плюс удалять, плюс управлять правами |

Типичная prod-настройка: у каждой команды роль **Editor** на своей папке, **Viewer** на кросс-командных analytics-папках, **none** на `internal/`. Workspace-owner управляет настройками доменов эксклюзивно.

См. также: [UTM-стратегия](/docs/best-practices/utm-strategy), [Решение проблем с доменом](/docs/troubleshooting/domain-config).
