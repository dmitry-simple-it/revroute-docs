Мощная [платформа атрибуции](/docs/concepts/attribution) Revroute позволяет понять, насколько эффективно ваши ссылки конвертируются в реальных пользователей и доход.

![Conversion analytics](https://s3.revroute.ru/dub-public/assets/blog/introducing-dub-conversions.webp)

В этом руководстве мы узнаем, как отслеживать события конверсий с Revroute, используя серверное отслеживание.

<Note>

Рекомендуемый способ отслеживания конверсий в Revroute — серверное отслеживание, которое более надёжно, чем [клиентское отслеживание](/docs/quickstart/client).

</Note>

## Шаг 2: Установите скрипт Revroute Analytics

Далее необходимо установить [скрипт Revroute Analytics](/docs/sdks/client-side/installation-guides/manual).

Этот скрипт обнаруживает параметр запроса `rr_id` и сохраняет его как first-party cookie, который будет использоваться для атрибуции последующих событий конверсий исходной ссылке.

## Шаг 3: Подготовьте серверные вызовы

События конверсий отправляются с вашего бэкенда обычными HTTP-запросами к REST API RevRoute — отдельный SDK для этого не нужен, подойдёт любой HTTP-клиент вашего языка:

- [`POST /track/lead`](/docs/api-reference/endpoint/track-lead)
- [`POST /track/sale`](/docs/api-reference/endpoint/track-sale)

Запросы авторизуются секретным ключом (`dub_*`) в заголовке `Authorization` — как получить ключ и где его хранить, описано в разделе [«API: аутентификация»](/docs/api-reference/authentication). Секретный ключ нельзя отдавать в браузер: для клиентских вызовов есть отдельный publishable key.

<Warning>
  Держите секретный ключ в переменных окружения или менеджере секретов. Утечка
  ключа даёт доступ ко всем ресурсам воркспейса.
</Warning>

## Шаг 4: Отслеживайте события конверсий

Теперь самое интересное — отслеживание событий конверсий.

### Отслеживание событий лидов

Первое событие, которое нужно отслеживать — это событие `lead`. Оно происходит, когда пользователь выполняет действие, указывающее на интерес к вашему продукту или услуге. Это может быть:

- Регистрация аккаунта
- Добавление товара в корзину
- Подписка на рассылку

![A diagram showing how lead events are tracked in the conversion funnel](https://s3.revroute.ru/dub-public/assets/help/conversion-lead-event.png)

Наиболее распространённое событие лида — `Sign Up`, которое происходит при регистрации пользователя. В зависимости от используемого фреймворка аутентификации, вот несколько примеров отправки событий лида `Sign Up`:

<AuthProviders />

Событие лида служит источником истины для идентификации клиента и определения ссылки, по которой он пришёл. Это означает, что все последующие действия клиента (например, повышение тарифа, покупка продукта) будут автоматически атрибутированы исходной ссылке.

### Отслеживание событий продаж

Второе событие, которое нужно отправить — это событие `sale`. Оно происходит, когда пользователь покупает ваш продукт или услугу. Это может быть:

- Подписка на платный план
- Расширение использования (переход с одного плана на другой)
- Покупка продукта

![A diagram showing how sale events are tracked in the conversion funnel](https://s3.revroute.ru/dub-public/assets/help/conversion-sale-event.png)

Отправляйте события продаж с бэкенда после успешной оплаты через [эндпоинт API `POST /track/sale`](/docs/api-reference/endpoint/track-sale). Чаще всего `track/sale` вызывают из обработчика webhook'а биллинга (например, `payment.succeeded` от ЮКассы или ваш собственный внутренний webhook).

<Tip>
  Хотите отслеживать продажи без предварительного события лида? Передайте
  `clickId` напрямую вместе с данными клиента при вызове `track/sale` — полный
  список полей см. в [API
  Reference](/docs/api-reference/endpoint/track-sale).
</Tip>
