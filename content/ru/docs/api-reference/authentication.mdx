# API: аутентификация

В RevRoute есть два типа ключей — выбирайте подходящий под ваш кейс.

## Секретные API‑ключи (server‑to‑server)

Используются для доступа к REST API со стороны бэкенда. Это **секрет**, его нельзя отдавать в браузер.

- Заголовок: `Authorization: Bearer <token>`
- Хранение: переменная окружения / менеджер секретов
- Где взять: **Настройки** → **API-ключи** в блоке **Разработчик** (`/<workspace>/settings/tokens`, ключ вида `rr_*`)

Эти ключи используются для server-side эндпоинтов, например:

- `POST https://api.revroute.ru/track/lead`
- `POST https://api.revroute.ru/track/sale`

### Создание ключа

Нажмите **Создать API-ключ** и заполните окно: название, тип ключа и права доступа. Ключ показывается один раз — скопируйте его сразу после создания.

### Тип ключа: «Вы» или «Системный»

- **Вы** — ключ привязан к вашему аккаунту. Если вас удалят из рабочего пространства, ключ будет удалён.
- **Системный** — RevRoute добавит в рабочее пространство бота-участника и свяжет ключ с ним. Ключ не привязан к вашему аккаунту и не будет удалён, даже если вы покинете рабочее пространство. Этот тип подходит для интеграций, которые не должны зависеть от конкретного сотрудника. Создавать системные ключи может только владелец рабочего пространства.

### Права доступа

- **Все** — полный доступ ко всем ресурсам.
- **Только чтение** — доступ только для чтения ко всем ресурсам.
- **Ограниченный** — доступ к отдельным ресурсам: для ссылок, тегов, папок, доменов и рабочих пространств выберите **Нет**, **Чтение** или **Запись**, для аналитики — **Нет** или **Чтение**.

Выдавайте ключу только те права, которые нужны интеграции. Например, для выгрузки статистики достаточно чтения аналитики.

## Publishable keys (клиентское отслеживание конверсий)

Publishable key предназначен для подключения клиентского скрипта RevRoute и отправки conversion‑событий с фронтенда. Его можно использовать в клиентском коде, потому что возможности намеренно ограничены.

Где взять publishable key:

- В кабинете RevRoute: `/<workspace>/settings/analytics?step=connect` (ключ вида `rr_pk_*`)

Эти ключи используются для client-side эндпоинтов, например:

- `POST https://api.revroute.ru/track/lead/client`
- `POST https://api.revroute.ru/track/sale/client`

## Пример (cURL)

```bash
curl -X GET "https://app.revroute.ru/api/me" \
  -H "Authorization: Bearer <ваш_токен>"
```

## Ключи, выданные раньше

Ключи, выпущенные до перехода на префикс `rr_`, **продолжают работать** —
менять их не нужно: валидация принимает оба формата. Новые ключи выдаются
с префиксом `rr_`.
