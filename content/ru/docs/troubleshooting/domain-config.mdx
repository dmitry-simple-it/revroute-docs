Добавление кастомного короткого домена (например `go.acme.com`) требует двух вещей: DNS-записи указывают на RevRoute и успешно выпущен TLS-сертификат. Если что-то застряло — здесь типичные причины.

## Ожидаемая конфигурация

Для домена `go.acme.com`:

| Запись | Тип | Имя | Значение |
| --- | --- | --- | --- |
| Основная | `CNAME` | `go` | `cname.revroute.ru` |
| Верификация | `TXT` | `_revroute.go` | показывается в дашборде при настройке |

Дашборд показывает точные значения для **вашего** домена — копируйте дословно.

Для apex-домена (`acme.com` без поддомена) большинство DNS-провайдеров не разрешают `CNAME`. Используйте `ALIAS` / `ANAME`, где доступно (Cloudflare, Route 53, DNSimple), или четыре `A`-записи на IP RevRoute (тоже показываются в дашборде).

<a id="dns-not-detected"></a>
## DNS не определяется

Дашборд показывает **Проверка DNS** дольше 10 минут.

### Диагностика

```bash
# Проверяем CNAME через публичный резолвер
dig +short go.acme.com @1.1.1.1
dig +short go.acme.com @8.8.8.8

# Проверяем TXT-запись верификации
dig +short TXT _revroute.go.acme.com @1.1.1.1
```

Обе команды должны вернуть значения из дашборда. Если ничего — DNS ещё не опубликован.

### Типичные причины

| Причина | Решение |
| --- | --- |
| TTL ещё не истёк — старые записи в кэше | Подождите исходный TTL (часто 5 мин, иногда 24ч). Резолверы не обновляются досрочно. |
| Имя записи включает домен (например `go.acme.com.acme.com`) | У некоторых провайдеров нужно `go`, у других — полное имя. Читайте доки провайдера. |
| Неверный тип записи | Верификация это `TXT`, не `CNAME`. Основная — `CNAME`, не `A`. |
| Включён прокси (оранжевое облако Cloudflare) | Выключите прокси (серое облако) на `go` — RevRoute управляет своим edge. |
| Несогласованность trailing dot | `cname.revroute.ru.` (с точкой) и `cname.revroute.ru` могут вести себя по-разному. Пробуйте оба. |

### Cloudflare quick fix

Если DNS на Cloudflare и запись есть, но RevRoute её не видит:

1. Откройте DNS-вкладку для `acme.com`.
2. Кликните иконку облака около записи — она должна стать **серой** (DNS-only). Проксированная (оранжевая) ломает RevRoute.
3. Установите **TTL = Auto**.
4. Подождите 2 минуты, затем нажмите **Перепроверить** в дашборде RevRoute.

<a id="ssl-pending"></a>
## SSL-сертификат pending

DNS верифицирован, но дашборд показывает **Выдача сертификата** дольше 30 минут.

### Диагностика

```bash
# Попробовать получить новый домен по HTTPS
curl -vI https://go.acme.com
```

Если видите `SSL_ERROR_NO_CYPHER_OVERLAP` или `unable to get local issuer certificate` — сертификат ещё не выдан.

### Причины

| Причина | Решение |
| --- | --- |
| CAA-запись блокирует Let's Encrypt | `dig +short CAA acme.com` — если CAA-запись есть, убедитесь, что включает `letsencrypt.org`. |
| Домен в HSTS-preload, но cert ещё не валидируется | Подождите — обычно само разрешится после выдачи |
| Прокси перед RevRoute перехватывает HTTP-01-challenge | Отключите прокси на коротком домене |
| Rate-limit от Let's Encrypt | Если переслали домен 5+ раз за неделю, упёрлись в LE per-domain rate-limit. Подождите 24ч. |

Нажмите **Повторить SSL** в дашборде после устранения причины. Платформа ретраит автоматически каждые ~10 минут, но ручной толчок быстрее.

<a id="cname-conflicts"></a>
## Конфликты CNAME

DNS-провайдер отказывается добавить `CNAME` для `go.acme.com`.

### Причина

У вас уже есть `A`, `AAAA` или `TXT` запись на `go`. По RFC `CNAME` не может сосуществовать с другими типами записей на одном имени.

### Решение

Удалите существующую запись на `go` (предварительно убедившись, что она не нужна!), затем добавляйте `CNAME`. Типичные виновники:

- Старые `A`-записи на давно мёртвый сервер
- `TXT`-записи верификации от прошлых сервисов (Vercel, Netlify, GitHub Pages) — оставьте RevRoute, удалите остальные
- `AAAA`-запись, авто-создаваемая некоторыми провайдерами

Если действительно нужны обе — используйте другой поддомен для RevRoute (`r.acme.com`, `links.acme.com`).

<a id="mixed-records"></a>
## Смешанные записи / split-brain DNS

Домен правильно резолвится с вашего ноута, но дашборд говорит **Не верифицирован**, или наоборот.

### Причина

Разные DNS-записи видны разным резолверам — обычно потому что:

- В офисе есть приватный DNS-сервер с overrides
- Прежние NS не полностью делегированы на новые
- Запись добавлена не в ту зону

### Диагностика

```bash
# Публичные резолверы
dig +short go.acme.com @1.1.1.1
dig +short go.acme.com @8.8.8.8
dig +short go.acme.com @9.9.9.9

# Ваш локальный резолвер
dig +short go.acme.com
```

Если локальный резолвер возвращает другое — проблема в приватном/legacy DNS, чините его.

Если все публичные расходятся — пропагация зоны не завершена, ждите до TTL родительских NS (иногда 48ч).

## Застряло после фикса

Если уверены, что DNS правильно и SSL выпущен, но домен всё ещё не редиректит:

1. **Сбросьте CDN.** Браузер может держать HSTS-заголовок от прошлого сервиса.
2. **Тестируйте в incognito.** Без расширений, без Service Workers, без cookies.
3. **Hard-reload дважды.** Современные браузеры агрессивно кэшируют 301/308 — одной перезагрузки иногда мало.
4. **Попробуйте свежее устройство.** Чистый тест убирает client-side кэши.

## Удаление домена

Чтобы отвязать домен:

<Steps>
  <Step title="Мигрируйте или архивируйте все ссылки">
    Ссылки на удаляемом домене перестанут редиректить. Переместите на другой домен (`PATCH /links/bulk` с новым доменом) или примите потерю.
  </Step>
  <Step title="Удалите из RevRoute">
    `Настройки → Домены → <domain> → Удалить`.
  </Step>
  <Step title="Почистите DNS">
    Удалите `CNAME` и `TXT`-записи верификации — они больше не нужны.
  </Step>
</Steps>

См. также: [Управление ссылками](/docs/best-practices/link-management).
