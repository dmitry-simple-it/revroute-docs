Любая партнёрская программа притягивает фрод. Хорошая новость: ~95% механически обнаруживается и блокируется правилами — для очевидных кейсов не нужны ML или ручной review. Здесь — правила, которые мы рекомендуем включить с первого дня.

## Типы фрода

| Категория | Как выглядит |
| --- | --- |
| **Бот-трафик** | IP датацентров, headless-браузеры, без JS-исполнения, одинаковые user-agent'ы волнами |
| **Click farms** | Много слабо-вовлечённых кликов с дешёвых residential-прокси, часто волнами |
| **Self-referrals** | Партнёр конвертирует себя через email друга или burner-аккаунт |
| **Cookie stuffing** | Сайт автозагружает партнёрские ссылки в невидимых iframe/попапах, перетирая легитимные cookies |
| **Coupon hijacking** | Партнёр вставляет свой реф-код на checkout для органических клиентов |
| **Friendly fraud / chargebacks** | Реальный клиент оспаривает платёж после выплаты комиссии |

Первые четыре блокируются правилами ниже. Последние два требуют политики (окно возвратов до релиза комиссии).

## Встроенные защиты RevRoute

Включены по умолчанию; проверьте в `Настройки → Программа → Фрод`:

- **Фильтрация IP датацентров** — клики из известных облаков (AWS, GCP, Azure, Hetzner, OVH и т.д.) пишутся, но не зачисляются
- **Детект бот user-agent'ов** — известные краулеры (Googlebot, GPTBot, мониторинги) не инкрементят счётчики
- **Per-IP rate-limit на клики** — всплески выше порога с одного IP трокаются
- **Блок self-referral** — клики, где IP совпадает с последним login-IP партнёра, не зачисляются

## Рекомендуемые правила к включению

Помимо дефолтов, включите:

- **Cooldown между кликами** — один IP + одна ссылка = один клик в окне 1 час. Останавливает базовые click-farm'ы.
- **Allow-list стран** — ограничьте комиссии странами, где продаёте. Бразильские клики для US-only продукта почти наверняка фрод.
- **Минимальная длительность сессии** — требовать, чтобы analytics-скрипт зафайерил `pageview`, прежде чем клик считается «квалифицированным». Фильтрует мгновенные bounces.
- **Allow-list IP на партнёра** — для партнёров, настаивающих на тестировании своей ссылки, whitelist'те IP и исключайте из зачисления.
- **Conversion delay** — держите sale-события N часов перед созданием комиссии. Отменяйте при возврате в этом окне.

## Базовый набор правил фрода

Для большинства B2C-программ это хорошая отправная точка:

```yaml
clicks:
  ignore_datacenter_ips: true
  cooldown_minutes: 60
  country_allowlist: [US, CA, GB, DE, FR, AU]   # под ваш рынок

leads:
  require_email_verification: true
  min_session_seconds: 5

sales:
  hold_minutes: 1440        # 24ч перед созданием комиссии
  cancel_on_refund: true
```

Сужайте country-list и снижайте `cooldown_minutes` только если видите ложно отсекаемый легитимный трафик.

## Паттерны для алертинга

Даже с правилами на месте, следите еженедельно:

- Партнёр с click → lead коэффициентом в 100× выше среднего по программе (часто = бот-сигнапы)
- Партнёр с 0% lead → sale конверсией при высоком объёме лидов (= фейковые сигнапы)
- Партнёр, чьи конверсии идут с одного IP-диапазона (= self-referrals)
- Внезапный спайк `direct` или `(none)` referrers среди кликов партнёра (= невидимый iframe-stuffing)

Еженедельный SQL по потоку событий достаточен — алертите команду на выбросы.

## Гигиена со стороны партнёра

Облегчите честным партнёрам оставаться честными:

- **Чёткие ToS.** Прямо укажите, что self-referrals, paid search по бренд-кейвордам и cookie-stuffing — основание для отключения.
- **Документированное окно review.** «Комиссии релизятся через 14 дней после продажи, после клиринга возвратов.» Это честно и стандартно.
- **Авто-пауза комиссий новых партнёров** на первые 30 дней, пока человек не апрувит. Фродеры уходят; честные партнёры спокойно ждут.
- **Канал репортинга.** Клиенты, видящие подозрительный попап с вашим брендингом, должны знать, куда писать.

## Если что-то проскочило

Если обнаружили фрод после выплаты:

<Steps>
  <Step title="Заморозьте партнёра">
    Приостановите партнёра немедленно, чтобы остановить дальнейший ущерб. На паузе он не зарабатывает и не выводит.
  </Step>
  <Step title="Соберите evidence">
    Логи кликов, IP лидов, тайминг конверсий, refund rate. Сохраните — пригодится, если партнёр оспорит отключение.
  </Step>
  <Step title="Откатите комиссии">
    Пометьте затронутые комиссии как `void`. Будущие выплаты их не включат; уже выплаченные становятся clawback против будущих заработков.
  </Step>
  <Step title="Сообщите">
    Email партнёру с конкретной причиной и evidence. Большинство фродеров исчезают; редкие честные кейсы получают справедливую апелляцию.
  </Step>
  <Step title="Заштопайте правило, которое промахнулось">
    Каждый инцидент — дыра в правилах. Добавьте правило, regression-запрос, идите дальше.
  </Step>
</Steps>
